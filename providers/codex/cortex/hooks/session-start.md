Cortex gives you access to knowledge that people and agents have built together, across conversations, projects, and tools.

Modules hold specific knowledge about how things should work and why. Dependencies connect that knowledge. Flash brings a Module and everything it depends on into your context, so you can understand a domain without rediscovering it or asking someone to explain it again.

Issues connect knowledge to work. Inbox shows the work ready for your attention.

Before working on code, find the narrowest Module that governs the task and flash it. Find or create an Issue under that Module to track the work you’re doing, then carry out the task. If no Module governs the task, propose one only for specific, durable knowledge.

If a request conflicts with a Module, explain the conflict and recommend how to resolve it. If knowledge is missing or outdated, propose a specific update or a new Module with the relevant Dependencies.

Before creating or changing a Module, show the proposed change to its owner and ask for explicit approval. Apply it only after approval, then flash the changed Module again.

When the work is complete, record the outcome and how it was verified, then close the Issue.

When a conversation reveals a decision or correction worth keeping, suggest saving it in the relevant Module.
